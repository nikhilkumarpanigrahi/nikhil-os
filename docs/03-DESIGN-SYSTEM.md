# NIKHIL//OS --- Design System

## 1. Design Goal

The interface should communicate:

> premium developer product + serious systems engineering + AI research
> environment

It should not look like:

-   a generic portfolio
-   a cyberpunk landing page
-   a macOS clone
-   a Windows clone
-   an AI-generated template
-   an RGB gaming interface

## 2. Visual References

Use the product discipline of:

-   Linear
-   Raycast
-   Arc
-   modern developer tools
-   Linux workstations
-   AI research interfaces

Use Arch Linux as philosophical inspiration, not as a visual clone.

## 3. Brand

Primary name:

# NIKHIL//OS

Subtitle:

**An AI-native personal computing environment.**

Possible compact mark:

`N//OS`

## 4. Color System

Base:

``` text
Background:      #08090A
Surface:         #0E1012
Elevated:        #15181C
Border:          #24282D
Primary Text:    #F5F7FA
Secondary Text:  #8B929C
```

Use one signature accent for:

-   active state
-   AI status
-   selected nodes
-   links
-   important telemetry

Avoid rainbow accents.

## 5. Typography

UI:

-   Inter
-   Geist
-   SF Pro where available

Technical/system:

-   JetBrains Mono

Use sans-serif for normal application content.

Use monospace for:

-   terminal
-   telemetry
-   logs
-   system status
-   code
-   process data

## 7. Landing Page

Before entering the OS, provide a premium product landing page.

Hero:

``` text
NIKHIL//OS

A personal computing environment
built from scratch.

[ ENTER NIKHIL//OS ]
[ EXPLORE ARCHITECTURE ]
```

Below:

-   systems
-   AI
-   ML
-   architecture
-   selected work
-   technical stack

## 8. Boot Experience

Keep it under 3--4 seconds.

Show real subsystem states:

``` text
SYSTEM              STATUS

Kernel              ● READY
AI Core             ● READY
Knowledge           ● READY
Network             ● READY
Filesystem          ● READY
```

Avoid fake cinematic loading.

## 9. Desktop

The desktop should feel like a modern developer workstation.

Use:

-   restrained borders
-   high information density
-   clear hierarchy
-   keyboard navigation
-   subtle transitions
-   real telemetry

## 10. Window Design

Windows should support:

-   drag
-   resize
-   minimize
-   maximize
-   close
-   focus
-   z-index
-   snapping
-   keyboard shortcuts

Do not over-style the chrome.

## 11. Command Palette

`Cmd/Ctrl + K`

Interface inspired by Raycast.

Capabilities:

-   search applications
-   search projects
-   query AI
-   navigate
-   run safe OS commands
-   jump to evidence
-   open recruiter mode

## 12. Applications

Each application should feel like a standalone premium product.

### Projects.app

Filters:

-   All
-   AI/ML
-   Backend
-   Systems
-   Open Source

Cards show:

-   title
-   short description
-   technologies
-   evidence
-   architecture

### Architecture.app

Interactive diagrams.

Nodes should reveal:

-   responsibility
-   technology
-   data flow
-   rationale
-   failure modes

### Recruiter.app

Minimal, conversion-focused.

### AI.app

Agent interface, not a chatbot clone.

### Developer.app

Deep technical inspection.

## 13. Motion

Motion must communicate state.

Good:

-   window transitions
-   graph movement
-   command palette opening
-   loading states
-   status changes
-   subtle hover feedback

Avoid:

-   excessive particles
-   spinning logos
-   glowing text
-   giant 3D objects
-   fake terminal typing
-   long boot sequences

## 14. Responsive Design

Desktop:

Full OS experience.

Tablet:

Workspace experience with collapsible navigation.

Mobile:

Focused application interface:

``` text
NIKHIL//OS

[ AI ]
[ Projects ]
[ Resume ]
[ Experience ]
[ System ]

>_
```

Do not squeeze desktop UI into a phone.

## 15. Accessibility

Support:

-   keyboard navigation
-   focus indicators
-   reduced motion
-   semantic labels
-   sufficient contrast
-   screen-reader-compatible controls
-   accessible terminal output

## 16. Seniority Signal

The UI should communicate:

-   restraint
-   hierarchy
-   consistency
-   observability
-   technical confidence
-   product thinking

The design should make complex internals feel simple.

## 17. Design Rule

> Motion communicates system state.\
> Visual complexity comes from information, not decoration.
